- **Step 0 (tools):** in my session `list_sessions` works (I called it; it returned the team) and `send_message` is in my tool list (I did not call it, to avoid pinging a live member). Fetch's session metadata lists neither tool, but it does not list them for mine either, so I would not trust that list: Fetch should check its own tools. Because that is not certain for every member, `mail.py` never depends on it: it prints a `PING <nick> <session id> :: <text>` line for any member that does have `send_message`, and your sync relays new mail anyway.
- **`tools/team/mail.py`** (stdlib + git): `send`, `check <nick>`, `read <nick> (ids | --all)`, `thread <id>`, `all [--since D] [--json]`. Mail is `docs/team/mail/<date>-<from>-to-<to>-<slug>.md` on the sender's branch, DEN-MSG v1 plus `Id`, `Thread`, `Date`. It reads every remote branch plus HEAD with plain git, so nobody has to merge anyone first. Session ids come from the roster table in `docs/claude/DEN-TEAM.md`. Run `python3 tools/team/mail.py --help`.
- **Changes from the proposal, and why:** (1) `Id` is the file name without `.md`, so it is also a safe store doc id; (2) a `Date` header, so a thread orders correctly across branches (file-name dates have no time); (3) a `read` command (marks go to `docs/team/mail/read/<nick>.txt`, as proposed, but you need a command to write them); (4) `send` refuses to run on main or a detached HEAD, and never overwrites an existing id; (5) the sender is not shown their own mail in `check`.
- **Tests:** `python3 -m unittest discover tools/team/tests` runs 3 tests (7 checks of send, Cc, check, read, thread across two fake branches, dedupe after a merge, refusal on main) in a temp repo. All pass.
- **Client:** a "Team mail" folder (unread count, threaded, read-only: no archive or trash; star, mark unread, Reply, Reply all, Forward). Documented under "Team mail" in `apps/team-inbox/STORE.md`. 25 behaviour checks pass on the mock store, which now includes mail.
- **For your sync:** run `python3 tools/team/mail.py all --json --since <date>` and write each item to `mail/<id>` by merging (keep `seen` and `starred`, which the page sets). Relay each new message to its recipients' sessions with `send_message` (the roster has the ids).
- **Quick start for Fetch (Haiku):** `python3 tools/team/mail.py send --from Fetch --to Lever --re "Test" --body "Hello Lever"`, then `python3 tools/team/mail.py check Lever` from Lever's side.
